Actividades: Modificar el MiniCRUD

Tres ejercicios guiados para extender el proyecto base agregando, cambiando y reorganizando atributos a través de todas las capas MVC.

¿Cómo funcionan estas actividades?
Cada actividad parte de un proyecto que ya funciona y te pide transformarlo en otro. El objetivo no es solo que el código quede igual al de la solución: es que entiendas por qué hay que tocar cada archivo y qué pasa si te saltás alguno.

Antes de escribir código, respondé las preguntas orientadoras. Después seguí los pasos en orden. Al final, probá agregar una persona y verificá que el dato nuevo aparezca en la lista.
  • Actividad 1 — Agregar sueldo (double) · referencia resuelta
  • Actividad 2 — Agregar email (String) · individual
  • Actividad 3 — Reemplazar sueldo por categoria con <select> · desafío
1

Agregar el atributo sueldo

De minicrud0 → minicrud0-mod1 · Referencia resuelta — estudiar antes de las siguientes

Referencia double 4 archivos
Objetivo

El proyecto base (minicrud0) solo guarda código y nombre de cada persona. Tu tarea es agregar el atributo sueldo (número decimal) y hacer que aparezca en el formulario de alta y en la lista.

PersonaVO: cod, nombre → cod, nombre, sueldo
Preguntas orientadoras — respondelas antes de tocar código
  1. ¿En qué clase Java se define la estructura de datos de una Persona? ¿Cómo se llama el patrón de diseño que usan las clases que terminan en VO?
  2. ¿Qué tipo de dato Java usarías para representar un sueldo con decimales? ¿Por qué no usarías int?
  3. ¿Para qué sirve el getter de un atributo? ¿Qué relación tiene con la expresión ${p.sueldo} que vas a escribir en el JSP?
  4. ¿Qué archivo Java recibe los datos que el usuario envía desde el formulario? ¿Por qué es necesario usar Double.parseDouble() para el sueldo pero no para el nombre?
  5. ¿Cuántos archivos JSP vas a tener que modificar? ¿Cuál es la diferencia entre el formulario y la lista?
  6. ¿Por qué no es necesario modificar PersonaDAO.java?
Consejo antes de empezar
Antes de escribir una sola línea, abrí los 4 archivos que vas a modificar y leelos completos. Identificá exactamente dónde va cada cambio. La mayoría de los errores vienen de no leer el código que ya existe.

01
PersonaVO.java

Agregar el atributo y actualizá constructor, getter, setter y toString

Declarar private double sueldo. Recordá que el constructor con parámetros también debe recibir el nuevo dato.

PersonaVO.java — cambios
// Atributo nuevo private double sueldo; // Constructor actualizado (3 parámetros ahora) public PersonaVO(int cod, String nombre, double sueldo) { this.cod = cod; this.nombre = nombre; this.sueldo = sueldo; // ← nueva línea } // Getter y setter public double getSueldo() { return sueldo; } public void setSueldo(double sueldo) { this.sueldo = sueldo; } // toString actualizado return "PersonaVO{cod=" + cod + ", nombre=" + nombre + ", sueldo=" + sueldo + '}';

Pregunta de verificación: Si el JSP llama a ${p.sueldo}, ¿a qué método Java llama internamente la Expression Language?

02
PersonaControladorServlet.java

Leer el parámetro sueldo del request

En el método privado agregar(), el Servlet lee los datos del formulario con request.getParameter(). Todos los parámetros llegan como String; hay que convertir el sueldo a double.

PersonaControladorServlet.java — método agregar()
private void agregar(HttpServletRequest request, ...) throws IOException { int codigo = Integer.parseInt(request.getParameter("codigo")); String nombre = request.getParameter("nombre"); double sueldo = Double.parseDouble(request.getParameter("sueldo")); // ← nuevo dao.agregar(new PersonaVO(codigo, nombre, sueldo)); // ← 3er arg response.sendRedirect(...); }

Pregunta de verificación: ¿Qué excepción lanzaría esta línea si el usuario escribe letras en el campo sueldo? ¿Cómo podrías protegerte de eso más adelante?

03
persona-form.jsp

Agregar el campo de sueldo en el formulario

El atributo name del input debe coincidir exactamente con el nombre que el Servlet lee con request.getParameter(). Usamos type="number" y step="0.01" para permitir decimales.

persona-form.jsp — dentro del <form>
<label>Nombre</label> <input type="text" name="nombre" required /> <label>Sueldo</label> <input type="number" name="sueldo" step="0.01" required /> <button class="btn" type="submit">Guardar</button>

Pregunta de verificación: Si cambiás el name de este input a "salario" pero en el Servlet seguís usando getParameter("sueldo"), ¿qué valor recibirías? ¿El proyecto tiraría error en compilación o en ejecución?

04
persona-lista.jsp

Mostrar la columna Sueldo en la tabla

Hay dos lugares en el JSP: el header de la tabla (<th>) y dentro del <c:forEach>, una celda <td> por cada persona.

persona-lista.jsp — dos cambios
<!-- 1) En el <thead> --> <th>Código</th> <th>Nombre</th> <th>Sueldo</th> <th>Acciones</th> <!-- 2) Dentro del <c:forEach var="p"> --> <td>${p.codigo}</td> <td>${p.nombre}</td> <td>${p.sueldo}</td> <td class="actions">...</td>

Pregunta de verificación: ¿Qué pasaría si agregás el <th> pero te olvidás el <td> dentro del forEach? ¿Y al revés?

Para verificar que todo funciona
Desplegá el proyecto, entrá a Agregar Persona, completá el formulario con los tres campos y guardá. La tabla de listado debe mostrar código, nombre y sueldo. Si algo no aparece, revisá si los name del form coinciden con los getParameter() del Servlet.

Reemplazar sueldo por categoria con <select>

De minicrud0-mod2 → minicrud0-mod3 · Desafío — combina agregar y quitar

Desafío Quitar atributo Agregar atributo select HTML
Objetivo

Esta actividad es diferente: no solo agregás un atributo nuevo, sino que reemplazás uno existente. El atributo sueldo (double, valor libre) se elimina y en su lugar aparece categoria (String con tres opciones fijas: "Junior", "Semi-Senior" y "Senior"). En el formulario, en lugar de un campo de texto libre, el usuario elige de una lista desplegable.

PersonaVO: sueldo (double) → categoria (String)
Formulario: <input number> → <select>
Preguntas orientadoras — respondelas antes de tocar código
  1. ¿Qué diferencia hay entre agregar un atributo y reemplazarlo? ¿Cuántos pasos adicionales implica quitar algo?
  2. ¿Qué tipo de dato Java usarías para categoria si las opciones son "Junior", "Semi-Senior" y "Senior"? ¿Podría ser un int? ¿Cuáles serían las ventajas y desventajas de usar un enum en lugar de un String?
  3. El elemento HTML <select> tiene varias etiquetas <option> adentro. ¿Cómo llega el valor seleccionado al Servlet? ¿Con qué método lo leerías?
  4. Cuando el usuario elige una opción de un <select>, ¿el valor que llega es el texto del <option> o el atributo value? ¿Qué pasa si no ponés el atributo value?
  5. ¿Es necesario modificar PersonaDAO.java para este cambio? Justificá tu respuesta.
  6. ¿Qué ventaja tiene ofrecer opciones fijas (un select) frente a dejar que el usuario escriba la categoría libremente?

PersonaVO.java

Quitar sueldo, agregar categoria

Eliminá la declaración de double sueldo y todos sus métodos. Agregá String categoria con su getter y setter. Actualizá el constructor para que reciba cod, nombre, email, categoria (en ese orden).

PersonaVO.java — antes y después
// ── QUITAR ────────────────────────── private double sueldo; public PersonaVO(int cod, String nombre, double sueldo, String email) {...} public double getSueldo() { return sueldo; } public void setSueldo(double sueldo) { this.sueldo = sueldo; } // ── AGREGAR ───────────────────────── private String categoria; public PersonaVO(int cod, String nombre, String email, String categoria) {...} public String getCategoria() { return categoria; } public void setCategoria(String categoria) { this.categoria = categoria; }

Reflexión: ¿Qué pasaría si te olvidás de quitar el getter de sueldo pero sí quitás el atributo? ¿El compilador te avisa? ¿Y si dejás el getter pero usás ${p.sueldo} en el JSP — cuándo falla eso?

02
PersonaControladorServlet.java

Actualizar el método agregar() del Servlet

Quitá la línea que leía el sueldo y convertía con Double.parseDouble(). En su lugar, leer categoria directamente como String — igual que el nombre o el email.

Método agregar() — resultado esperado
private void agregar(...) throws IOException { int codigo = Integer.parseInt(request.getParameter("codigo")); String nombre = request.getParameter("nombre"); String email = request.getParameter("email"); String categoria = request.getParameter("categoria"); // ← nuevo // double sueldo = Double.parseDouble(...); // ← eliminar dao.agregar(new PersonaVO(codigo, nombre, email, categoria)); response.sendRedirect(...); }

Reflexión: ¿Por qué el valor que llega desde un <select> se lee igual que el de un <input>? ¿Cómo sabe el Servlet de dónde viene?

03
persona-form.jsp

Reemplazar el input numérico por un <select>

Borrá el bloque de label + input[sueldo] y escribí un <select> con tres <option>. El atributo name del <select> debe ser "categoria".

persona-form.jsp — bloque a reemplazar
<!-- QUITAR esto --> <label>Sueldo</label> <input type="number" name="sueldo" step="0.01" required /> <!-- AGREGAR esto --> <label>Categoría</label> <select name="categoria" required> <option value="Junior">Junior</option> <option value="Semi-Senior">Semi-Senior</option> <option value="Senior">Senior</option> </select>

Reflexión: ¿Qué valor llega al Servlet si el atributo value de una opción es diferente al texto que el usuario ve? Por ejemplo: <option value="J">Junior</option> — ¿qué recibiría getParameter("categoria")?

Verificación completa

  3. Agregá personas con diferentes categorías y verificá que cada una guarda la suya.
Preguntas de cierre — para discutir o investigar
